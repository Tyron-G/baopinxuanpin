# 贴近生产化改造说明

> 日期：2026-06-04（北京时间）

## 1. 市场数据表化（P1）

- 趋势 / 竞争 / 供需数据以 H2 表为 **唯一数据源**：`category_trend`、`competition_data`、`supply_demand`（`data.sql` 种子）。
- 新增 `repository/market/MarketDataRepository` + `JdbcMarketDataRepository`，`InsightMarketDataService` 按可见品类 **IN 查询**，不再全表加载后内存过滤。
- 叙事与类目深度内容仍在 `content/`（`CategoryPlaybook` 等），与市场时序数据分离。

## 2. 竞品时间轴落库（P1）

- 新表 `competitor_timeline_point`（店铺 + 平台 + 品类 + 周序 + 热度/销量/说明）。
- 内置竞品：`data.sql` 种子；**用户 `POST /api/competitor` 新增时**由 `CompetitorTimelinePointSeeder` 写入 4 周基线节点（幂等，重复店铺不重复写）。
- `CompetitorTimelineRuleEngine` 统一基线规则；`CompetitorTimelineBuilder` 读库后按视图平台叠加加成，无记录时再规则回退。

## 3. 统一 `ApiResult<T>`（P2）

成功响应：

```json
{ "code": 0, "message": "ok", "data": { ... }, "path": "/api/...", "timestamp": 1717488000000 }
```

失败响应（`data` 为 `null`）：

```json
{ "code": 404, "message": "...", "data": null, "path": "...", "timestamp": ... }
```

- `ApiResultResponseAdvice` 包装 Controller 成功体。
- `GlobalExceptionHandler` 返回 `ApiResult.fail`。
- 前端 `api/http.ts` 自动解包 `data`。

## 4. 品牌建档校验（P2）

- `BrandRequest.targetPlatforms`：`@SupportedPlatforms`（天猫 / 淘宝 / 抖音 / 小红书，至少 1 个）。
- `BrandProfileNormalizer`：平台去重、排除品类去重后入库。

## 5. 一致性加固（2026-06-04 续）

- `GET /api/opportunity/{cardId}/points` 增加 `brandId`，经 `requireVisible` 与详情/报告一致。
- `ActionStatusUpdateRequest.status`：`@AllowedActionStatus`（待执行 / 待确认 / 进行中 / 已完成 / 已放弃）。
- `CompetitorRequest.platform`：`@SupportedPlatform` 单平台白名单。
- 前端 `getApiErrorMessage` 统一展示后端 `message`；`hasSavedBrand` 仅看 `selection-brand-saved`。
- 移除已废弃的 `ApiErrorResponse`。

## 5. Spring 事务与 AOP 可观测性（P1）

- 新增 `spring-boot-starter-aop`，通过 `@TrackedExecution` 标记关键服务方法。
- `TrackedExecutionAspect` 统一输出 `tracked-execution label=... elapsedMs=...`，用于后续接 Actuator / Micrometer 前的轻量耗时观测。
- `ActionStatusTracker.update`：
  - 改为 `update -> insert -> duplicate 后重试 update`
  - 配合表唯一键 `UNIQUE (insight_card_id, action_title)`，避免重复写入
- `CompetitorService.add`：
  - 改为 `@Transactional`
  - 捕获 `DuplicateKeyException` 后回退到已存在记录，避免并发新增异常外抛

## 6. 取舍说明

- 这轮没有强行引入 `ThreadLocal`、显式锁、线程池、`BeanPostProcessor`。
- 原因是当前主要瓶颈并非内存共享并发，而是持久化写入一致性和服务调用可观测性。
- 后续若要继续贴近生产，优先级更高的是：
  - 将字符串时间字段逐步收敛为 `LocalDateTime`

## 7. Actuator 与指标（P1）

- 已接入 `spring-boot-starter-actuator`。
- 暴露端点：`health`、`info`、`metrics`、`prometheus`。
- 新增 `SelectionDataHealthIndicator`：
  - 基于 `brand` 表种子数据做业务就绪检查
  - `brandCount > 0` 时返回 `UP`
- `TrackedExecutionAspect` 除日志外，额外上报 Micrometer `Timer`：
  - 指标名：`selection.tracked.execution`
  - 标签：`label`、`domain`
- 新增 `SelectionInfoContributor`：
  - 暴露应用名、版本、发布日期、运行端口、样例数据版本
- 新增 `WriteRequestMetricsInterceptor`：
  - 指标名：`selection.write.requests`
  - 标签：`method`、`endpoint`、`domain`、`outcome`、`status`
  - 当前覆盖所有 `/api/**` 写请求（POST / PUT / PATCH / DELETE）
- 新增 `ExceptionMetricsRecorder`：
  - 指标名：`selection.error.responses`
  - 标签：`domain`、`error_code`、`exception`、`status`
  - 由 `GlobalExceptionHandler` 在 400 / 404 / 500 响应时统一计数
  - 当前已落地的错误码示例：
    - `brand_not_found`
    - `insight_card_not_found`
    - `insight_card_excluded`
    - `constraint_violation`
    - `request_validation_failed`
    - `internal_server_error`
- 说明：
  - `prometheus` 端点在真实应用启动环境可访问
  - `MockMvc` 集成测试环境下不稳定暴露该端点，因此测试仅覆盖 `health / info / metrics`
