# P0 详细开发实施方案

## 一、范围说明

本方案只覆盖上一份任务清单中的 P0 三项：

1. 主流程收敛
2. 统一评分、置信度、风险解释
3. 品牌约束深度参与推荐

目标不是继续堆页面，而是把当前本地 MVP 改造成一条更像真实 SaaS MVP 的“推荐决策链”。

> 术语口径：[`术语与口径说明_20260604.md`](术语与口径说明_20260604.md)

### 当前问题摘要

#### 1. 主流程虽然有页面，但链路不够强

- 路由层已经有 `data-prep / radar / insight / competitor / opportunity`。
- 但用户看到的是“多个模块”，不是“一条连续流程”。
- 目前仍较依赖侧边栏和用户主动理解业务逻辑。

#### 2. 推荐是存在的，但评分体系还不统一

- `InsightCardView` 只有 `pinned / budgetCompatible / matchTags`。
- `InsightSummary` 主要是结论型文案。
- `OpportunityDetail` 已有较丰富内容，但缺统一评分拆解对象。
- `InsightService` 里仍存在固定规则和静态文案驱动。

#### 3. 品牌约束参与还不够深

- `BrandContextEngine` 已实现：
  - 排除品类
  - 预算兼容
  - 目标品类优先
- 但还缺：
  - 平台匹配
  - 利润下限匹配
  - 备货周期匹配
  - 供应链适配度
  - 未入选原因

## 三、P0-1 主流程收敛实施方案

## 目标

将系统主流程固定为：

`数据准备 -> 信号雷达 -> 洞察发现 -> 爆品机会 -> 选品报告`

让每一个页面都回答三件事：

1. 我现在在哪一步

## 四、P0-2 统一评分、置信度、风险解释实施方案

## 目标

统一“信号 -> 洞察 -> 机会”三层推荐逻辑，形成一套一致的评分语言。

## 建议评分模型

总分 = 趋势分 + 竞争分 + 供需分 + 品牌匹配分 - 风险扣分

### 建议分段

| 字段 | 区间 | 说明 |
|---|---|---|
| trendScore | 0-30 | 搜索增速、社媒增速、榜单异动 |
| competitionScore | 0-20 | CR5、SKU 密度、同质化 |
| supplyGapScore | 0-20 | 价格带缺口、供需比 |
| brandFitScore | 0-20 | 平台、预算、利润、周期、供应链 |
| riskPenalty | 0-10 | 进入门槛、售后复杂度、红海程度 |
| totalScore | 0-100 | 综合机会得分 |
| confidence | 0-100 | 推荐置信度 |

## 五、P0-3 品牌约束深度参与推荐实施方案

## 目标

让品牌上下文从“展示信息”升级为“真正参与打分和解释”。

## 当前基础

`BrandContextEngine.java` 已支持：

- 排除品类过滤
- 目标品类优先
- 预算兼容判断
- 匹配标签

但还缺少结构化“适配度”与“未入选原因”。

  - `BrandFitDetail.java`

## 规则增强方案

### 1. 平台匹配

#### 规则

- 品牌目标平台包含抖音：
  - 内容驱动型品类加分
- 品牌目标平台包含天猫/淘宝：
  - 搜索稳定型品类加分
- 平台完全不匹配：
  - 降权

#### 数据实现

先用内置规则（样例数据 + 规则引擎）：

- 在类目级别配置平台倾向
- 通过 DTO 返回平台适配说明

### 2. 利润下限匹配

#### 规则

- 若预估净利低于品牌利润下限：
  - 扣分
  - 风险提示

### 3. 备货周期匹配

#### 规则

- 爆品窗口短、但品牌备货周期长：
  - 降低机会等级
- 周期短且可快速验证：
  - 加分

### 4. 供应链资源匹配

#### 规则

- 若品牌已有对应供应链：
  - 提高可行性
- 若需要复杂电子/售后体系，品牌无相关资源：
  - 扣分
